# Agent 协作约定（先答后改）

> **团队默认工作方式**（2026-05-22 起）：与 Cursor / 其他 Agent 协作时，**先回答问题、对齐理解，用户确认后再改代码或文档**；未经确认不直接修改仓库内容。

## 原则

1. **先回答**：对用户问题、现象描述、排查请求，先给出分析、原因判断与可选方案（必要时注明「仅分析，尚未改代码」）。
2. **再确认**：涉及改 `src/`、`tests/`、`docs/`、配置或 Git 时，用简短条目复述「将改什么、不改什么、如何验收」，等待用户明确同意（如「可以改」「按方案 A 做」）。
3. **后执行**：收到确认后再编辑、运行测试；**`git commit` / `git push` 须单独确认**（见下节）；若确认范围有变，先更新理解再动手。

## Token 节约与超时停手

为节约 token，并避免长时间沿错误方向试错，Agent 处理问题时默认采用分阶段方式：

1. **先只读诊断，不改代码**：先阅读相关文件、定位问题范围，并给出简短判断；如果问题原因不明确，不直接进入长时间试错。
2. **写入前必须列范围并等待确认**：说明准备改哪些文件、为什么改、不改哪些内容、用户如何验收。
3. **单次执行预算**：如果一个问题预计需要超过 5 分钟，或实际连续处理超过约 5 分钟仍无明确结论，Agent 必须停止并汇报已确认的信息、卡点、可能处理方向和推荐下一步。
4. **默认不主动跑完整测试**：代码写好后，Agent 只说明建议验收命令，由用户自行测试；只有用户明确要求，或测试非常短且对确认修改必要时，才运行必要测试。
5. **禁止长时间盲目试错**：不允许连续反复改代码、跑命令、看输出超过约 5 分钟；如果没有新证据，应先停下来重新评估方法。

## 沟通语言

项目使用者以审计专业人员为主，可能只有少量 IT 基础。Agent 回复时应默认使用通俗、业务可判断的表达：

- **先说结论**：例如“建议先补 K.01 测试，不改规则逻辑”。
- **再说影响**：说明这会影响质检报告、底稿标注、还是只影响测试稳定性。
- **少说黑话**：必须出现技术词时，顺手翻译成审计人员能理解的话。例如：
  - `ingest`：读取 Excel 底稿、识别工作表和字段。
  - `rules`：按 checklist/SOP 自动检查。
  - `report`：生成质检报告、HTML 摘要和底稿批注。
  - `pytest`：跑自动测试，确认改动没有把已有检查弄坏。
- **方案按四件事写**：改什么、为什么改、不改什么、如何验收。
- **避免一次给太多技术细节**：除非用户追问，先给 2–5 条重点。

## 适用场景

| 场景 | 先答 | 确认后执行 |
| --- | --- | --- |
| 用户标注「请勿直接修改」「先回答」 | 必须 | 必须 |
| 排查 bug、解释规则/ingest 行为 | 必须 | 修代码前确认 |
| 新功能、改规则、改标注导出 | 可先给方案对比 | 必须 |
| 纯文档澄清、读 handoff | 直接回答 | 改文档前若影响口径仍建议确认 |

## Git 提交与推送（必须单独确认）

即使用户说「保存」「提交」「推送」，也**不要默认**直接 `git commit` / `git push`。须先：

1. **列清单**：`git status` / 拟 `add` 的文件列表；**明确不提交**项（如 `.env`、`scripts/_*.py`、`artifacts/_*`、未完成的 docs）。
2. **拟提交说明**：1–2 句 commit 意图；确认**不含** API 密钥（`.env` 仅在本地，`.env.example` 无真实 key）。
3. **等待确认**：用户回复「可以提交」「可以推送」或调整清单后再执行。
4. **执行后回报**：commit hash、是否已 push、远程分支。

**例外**（仍建议先列清单）：用户同一条消息中**同时**写明「不用确认，直接 commit 并 push」且范围已限定。

## 可不单独确认的情形（仍应先说明再改）

- 用户**同一条消息**里已写明「请修改/请实现」并给出足够验收标准（**不含** commit/push，除非同时写明且已列清单）；
- 用户明确「不用确认，直接做」；
- 仅修正用户刚指出、且范围唯一的笔误（如单文件拼写），并在回复中说明改了什么。

## 确认时应包含

- **目标**：要解决什么问题；
- **范围**：涉及模块/文件（如 `src/rules/`、`export_annotated_workbook.py`）；
- **不做什么**：避免误伤（如不动 `.env`、不整本 `openpyxl.save` 外链底稿）；
- **验收**：如何验证（命令、底稿样例、预期现象）。
