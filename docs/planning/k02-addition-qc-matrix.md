# K.02.1 新增测试质检矩阵（详细规划）

> 状态：规划沉淀。本文用于指导 K.02.1 新增测试的 ingest、report 与 rules 开发。
> 方法：模板定结构，SOP 定口径，ingest 先读对，report 先展示，rules 再判对。

## 一、开发原则

K.02.1 新增测试不能只按固定 sheet 名、固定单元格或固定行号判断。标准模板和 SOP 只能说明应有模块与执行口径，真实底稿中可能存在：

- sheet 名称变体，如 `K.02.1 新增测试`、`K.02.1 细节测试`、`新增测试`。
- 新增清单由项目组自定义、系统导出或另行插入，不一定与 SOP 模板同名。
- K.02.1 与 K.02.1a 的模块位置可能变化。
- 项目组可能在汇总页拒绝执行，也可能未在汇总页拒绝、但在 K.02.1 中写明不执行或无需抽样的理由。
- 选样工具可能是 Skywind，也可能存在 Smart Sampling 或人工抽样输出变体。

因此，K.02.1 的第一阶段目标是识别“执行路径”和“关键模块”，不直接按缺页或缺固定位置判定程序不到位。

## 二、模块总览

| 模块 | 名称 | 主要目的 | 第一阶段输出 |
| --- | --- | --- | --- |
| K2-A | 新增测试执行路径识别 | 判断项目组是执行、拒绝执行，还是在测试页中说明无需执行 | ingest + report |
| K2-B | 新增清单读取 | 读取新增清单字段、金额与新增方式 | ingest + report |
| K2-C | 样本总体定义 | 识别测试总体是否为购置新增原值 | ingest + report |
| K2-D | 总体金额勾稽 | 读取新增清单、K.02.1、K.01 后推之间的金额关系 | ingest + report，规则后置 |
| K2-E | 抽样策略与样本池 | 读取选样输出中的样本池、排除项、样本量和抽样方法 | ingest + report |
| K2-F | 选样结果一致性 | 对比选样输出样本与 K.02.1 实际测试样本 | ingest + report，规则后置 |
| K2-G | TOD 测试执行与结论 | 摘录每个样本的证据、差异和测试属性结论 | ingest + report，人工复核为主 |

## 三、K2-A 新增测试执行路径识别

### 业务目的

判断新增测试采用哪条执行路径，避免把“程序包不完整”简单等同于“程序执行不到位”。

### SOP 口径

汇总页可以拒绝执行新增测试，但拒绝理由应合理。例如：

- 本年度无新增固定资产。
- 新增资产原值小于 TE，且各单项资产均小于 TT。
- 无性质异常的单项新增资产。

若满足拒绝执行条件但未在汇总页拒绝，而是在 K.02.1 中写明说明，也不应机械判断为程序包不完整；应提示记录位置不一致并交由人工复核。

### ingest 需要读取

- 汇总页中 K.02.1 的执行状态、拒绝理由、source row。
- 是否存在新增清单。
- 是否存在 K.02.1 新增测试页。
- 是否存在 K.02.1a 新增选样输出页。
- K.02.1 中是否存在不执行或无需抽样说明，例如：
  - 无新增、本期无购置。
  - 小于 TE、小于 TT。
  - 无性质异常。
  - 无需执行、无需抽样、不执行详细测试。
  - 全部作为关键项或无需代表性抽样。

### 建议执行路径分类

| 路径 | 识别条件 | report 展示 | rules 边界 |
| --- | --- | --- | --- |
| `summary_waived` | 汇总页明确拒绝执行，且有拒绝理由 | 展示汇总页理由与相关金额上下文 | 交给 PSP 拒绝理由模块；K2-A 不按缺页报错 |
| `executed_package_complete` | 汇总页显示执行，且新增清单、K.02.1、K.02.1a 均识别到 | 展示三表证据 | 进入后续 K2-B 至 K2-G |
| `executed_package_incomplete` | 汇总页显示执行，但缺少关键页，且未识别替代说明 | 展示缺失项与已识别证据 | 第一阶段建议 `NEED_REVIEW`，成熟后再考虑升级 |
| `test_sheet_waiver_note` | 汇总页未拒绝或状态不清，但 K.02.1 中写明无需执行或无需抽样 | 展示测试页说明和汇总页状态 | 提示记录位置不一致，人工确认理由是否成立 |
| `unclear` | 汇总页、K.02.1、K.02.1a 均不足以判断路径 | 展示识别失败原因 | `NEED_REVIEW` |

## 四、K2-B 新增清单读取

### SOP 口径

新增清单格式不强制固定，但必须确保关键字段完整。新增测试的总体通常是购置新增原值，其他新增方式不应简单混入购置总体。

### ingest 需要读取

- 固定资产类别。
- 固定资产编号。
- 固定资产名称。
- 入账开始日期。
- 原值。
- 新增方式。
- 可选：使用寿命、残值率、月份、权重等折旧测试辅助字段。

### report 展示

- 新增清单来源 sheet。
- 记录数。
- 字段映射结果。
- 新增方式分布。
- 购置类原值合计。
- 非购置新增方式示例行。

### rules 边界

- 字段缺失可自动提示。
- 非购置新增应先 `NEED_REVIEW`，由人工确认是否单独分总体、索引其他 PSP/OSP 或设计额外程序。

## 五、K2-C 样本总体定义

### SOP 口径

新增测试的测试属性与固定资产购置新增相匹配。其他方式新增，如在建工程转入、企业合并、调拨、重分类等，与购置新增不具有相同或相似特征，应作为不同总体或使用其他 PSP/OSP。

### ingest 需要读取

从 K.02.1 中识别：

- 测试总体描述。
- 购置总金额 / 样本总体金额。
- 关键项目金额。
- 代表性抽样剩余总体。
- 是否存在非购置新增的说明或索引。

识别方式应按锚点扫描，不依赖固定单元格：

- `购置总金额`
- `样本总体`
- `测试总体`
- `关键项目`
- `代表性抽样`
- `剩余总体`
- `在建工程转入`
- `其他新增方式`

### report 展示

- 识别到的总体描述原文。
- 购置总金额。
- 关键项目金额。
- 剩余代表性总体金额。
- 非购置新增说明摘录。
- 识别置信度。

## 六、K2-D 总体金额勾稽

### SOP 口径

新增清单应与固定资产后推明细表核对一致。样本总体与新增清单、后推明细表存在差异的，应进行调查和说明；超过 SAD 的差异尤其需要关注。

### ingest 需要读取

- 新增清单购置原值合计。
- K.02.1 中记录的购置总金额。
- K.01 后推表购置金额。
- 差异金额。
- 是否需要进一步调查。
- 调查说明或 Notes。

识别方式应按锚点和相邻金额读取：

- `Breakdown`
- `后推`
- `K.01`
- `BKD`
- `差异`
- `是否需要进一步调查`
- `Notes`
- `调查`

### report 展示

- 三方金额：新增清单、K.02.1、K.01。
- 差异。
- SAD。
- 是否超过 SAD。
- 说明摘录。

### rules 边界

- 金额读不到任一侧时，不强判，输出读取风险或 `NEED_REVIEW`。
- 金额差异存在但说明是否充分，第一阶段由人工复核。

## 七、K2-E 抽样策略与样本池

### SOP 口径

选样输出应保留抽样工具记录。项目组应导入新增清单或本期购置清单，确定样本池总体金额、排除项、关键项、代表性样本量和抽样方法。

### ingest 需要读取

从 K.02.1a 中识别：

- 抽样工具类型或输出页类型。
- 已上传数据金额。
- 排除项金额与排除项类型。
- 样本池总体金额。
- 会计记录金额。
- 差额。
- 关键项数量与金额。
- 代表性样本量。
- 样本选择方法。
- 是否确认总体具有类似特征。

锚点示例：

- `源数据汇总`
- `样本池汇总`
- `已上传数据`
- `必要的数据排除项`
- `样本池总体金额`
- `会计记录`
- `差额`
- `关键项`
- `代表性样本量`
- `样本选择方法`
- `总体包含具有类似特征`

### report 展示

- 样本池金额表。
- 排除项摘要。
- 样本量摘要。
- 抽样方法。
- 识别置信度。

## 八、K2-F 选样结果一致性

### SOP 口径

选样输出中的样本应在 K.02.1 新增测试中执行测试。SOP 易错点明确关注：选样结果与 K.02.1 中测试的样本不一致。

### ingest 需要读取

从 K.02.1a 读取已选样本表：

- 源样本号。
- 抽样 ID。
- 样本类型。
- 固定资产类别。
- 固定资产编号。
- 固定资产名称。
- 入账开始日期。
- 原值。
- 新增方式。

从 K.02.1 读取实际测试样本表：

- 样本类型。
- 固定资产类别。
- 固定资产编号。
- 固定资产名称。
- 资产原价。
- 资本化日期。

表头识别应按字段组合，不依赖固定行号。

### report 展示

- 选样输出样本数量。
- K.02.1 实际测试样本数量。
- 可匹配样本数量。
- 未匹配样本摘要。
- 匹配所用字段和置信度。

### rules 边界

- 资产编号可稳定匹配时，可作为后续自动规则候选。
- 只有名称或金额弱匹配时，应先 `NEED_REVIEW`。
- 替换样本、关键项、代表性样本需要分别展示，不宜混在一个结论中。

## 九、K2-G TOD 测试执行与结论

### SOP 口径

对每个被选中测试的项目，项目组应检查第三方证据和会计分录，并确认：

- 资本化日期恰当，不应费用化。
- 历史成本按适用财务报告框架记录。
- 使用寿命和折旧方法适当。
- 资产归入适当固定资产类别。

### ingest 需要读取

从 K.02.1 测试表读取：

- 样本类型。
- 资产编号。
- 资产名称。
- 资产原价。
- 支持性文件金额。
- 证据描述。
- 差异。
- 测试属性 1 至 4 的结论。
- 异常情况说明或整体结论。

### report 展示

- 每个样本的证据描述是否为空。
- 支持性文件金额与资产原价差异。
- 测试属性结论摘要。
- 异常情况说明。

### rules 边界

- 金额差异可结构化展示，但差异原因是否充分通常需要人工复核。
- 证据描述为空、测试属性为空可作为规则候选；证据充分性本身应先 `NEED_REVIEW`。

## 十、建议开发顺序

1. K2-A：执行路径识别。
2. K2-C / K2-E：读取 K.02.1 总体区与 K.02.1a 样本池区。
3. K2-F：读取并匹配选样输出样本与实际测试样本。
4. K2-D：将 K.02.1 金额与新增清单、K.01 购置金额整合展示。
5. K2-G：读取 TOD 测试执行表，先展示后判断。
6. report：先输出 K.02 新增测试摘录区。
7. rules：在案例回归稳定后，再逐步落地样本一致性、字段缺失、金额差异调查等规则。

## 十一、第一阶段验收标准

第一阶段不要求新增 rules 结论。验收重点是读对：

- 能识别 K.02.1 的执行路径。
- 能识别新增清单、K.02.1、K.02.1a 是否存在及命名变体。
- 能摘录 K.02.1 总体金额、差异和测试样本表。
- 能摘录 K.02.1a 样本池金额和已选样本表。
- 能输出识别置信度和缺失原因。
- 对无法稳定读取的情况，不强判 `PASS` 或 `FAIL`。

## 十二、K.02.1 锚点取数清单与 coding/LLM 分工

K.02.1 新增测试的取数不得依赖固定单元格或固定行号。标准底稿模板用于确认应有模块，SOP 用于确认执行口径；真实底稿中应采用“锚点 + 结构 + 交叉校验”的方式取数。

总体分工原则：

- **coding 优先**：金额、表头、样本行、属性 1-4、公式重算、与新增清单/K.01/K.02.1a 的交叉校验。
- **coding + 文本摘录**：总体描述、关键项理由、差异说明、异常说明；先摘录展示，不直接强判。
- **LLM 可选辅助**：判断说明文字是否属于拒绝执行、总体是否混入非购置新增、关键项理由是否空泛、证据描述是否明显不足。LLM 输出只作为 `NEED_REVIEW` 背景，不覆盖确定性金额规则。
