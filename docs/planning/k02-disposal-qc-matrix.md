# K.02.2 处置测试质检矩阵（详细规划）

> 状态：规划沉淀（供评审）。本文用于指导 K.02.2 处置/报废测试的 ingest、report 与 rules 开发。  
> 方法：模板定结构，SOP 定口径，ingest 先读对，report 先展示，rules 再判对。  
> 对称参考：[k02-addition-qc-matrix.md](./k02-addition-qc-matrix.md)（K.02.1 新增测试）

## 一、开发原则

K.02.2 处置测试不能只按固定 sheet 名、固定单元格或固定行号判断。标准模板和 SOP 只能说明应有模块与执行口径，真实底稿中可能存在：

- sheet 名称变体，如 `K.02.2 处置测试`、`K.02.2 细节测试`、`处置测试`。
- 处置清单由项目组自定义、系统导出或自行编制（两年 FA list vlookup + JE），不一定与 SOP 模板同名。
- `K.02.2b 减少清单` / `K.02.2b 处置清单` 与 `处置清单` 并存。
- K.02.2 与 K.02.2a 的模块位置可能变化。
- 项目组可能在汇总页拒绝执行，也可能未在汇总页拒绝、但在 K.02.2 中写明不执行或无需抽样的理由。
- **程序包不完整 ≠ 程序执行不到位**（汇总拒绝、或测试底稿已有受限执行说明时，不应机械按缺页 FAIL）。

因此，K.02.2 的第一阶段目标是识别 **执行路径** 和 **关键模块**，不直接按缺页或缺固定位置判定程序未执行。

### 三表程序包（与汇总页联动）

| Sheet | 角色 |
| --- | --- |
| **处置清单** | 获取总体、与 K.01 核对、处置完整性考虑（主要程序在此页完成） |
| **K.02.2 处置测试** | 样本总体界定（处置/报废总金额、Breakdown 中处置金额等）、TOD 细节测试 |
| **K.02.2a 处置选样输出** | Skywind / 智能选样输出，索引抽样结果 |

汇总页若 **拒绝处置测试**，SOP 明确 **无需完成处置清单**；Agent 门控应与此一致。

## 三、DT-A 处置测试执行路径识别

### 业务目的

判断处置测试采用哪条执行路径，避免把「程序包不完整」简单等同于「程序执行不到位」。

### SOP 口径

**汇总页可拒绝执行**，理由应合理，例如：

- 本年度无处置固定资产。
- 处置资产 **净值** 小于 TE，且各单项处置净值小于 TT，且无性质异常单项。

**若在汇总页已拒绝**，则无需完成处置清单（SOP 处置清单程序）。

**若满足拒绝条件但未在汇总页拒绝**，而在 **K.02.2** 中写明说明（如「处置净值小于 TE，未执行抽样」），不应机械 FAIL「程序包不完整」；应提示 **汇总标记与测试底稿说明不一致**，交人工复核。

### ingest / rules 需要读取

| 信号源 | 读取项 |
| --- | --- |
| 汇总页 | K.02.2 / K.02.2a 组：执行状态、不执行理由、注意事项（notes） |
| 工作簿 sheet 列表 | 是否存在处置清单、K.02.2、K.02.2a（名称变体） |
| K.02.2 测试底稿 | 前若干行：不执行 / 小于 TE / 未抽样 / 本期无处置 等说明 |
| （可选 P1.5）K.01 + Lead | 处置变动净值、TE、TT：客观是否满足拒绝条件 |

K.02.2 说明扫描锚点示例：`不执行`、`未执行`、`无需执行`、`小于TE`、`低于TE`、`未抽样`、`本期无处置`、`净值小于`。

### 建议执行路径分类

| 路径 ID | 识别条件 | report 展示 | rules 边界 |
| --- | --- | --- | --- |
| `summary_waived` | 汇总页明确拒绝执行，且有拒绝理由 | 汇总理由 + 处置金额上下文（K.01/Lead） | 交给 **AE-003** 拒绝理由模块；**不**按缺三表报 program package |
| `executed_package_complete` | 汇总=是，且处置清单、K.02.2、K.02.2a 均识别 | 三表证据列表 | 进入 DT-B～DT-D |
| `executed_package_incomplete` | 汇总=是，缺关键页，且 **无** 测试页/汇总受限说明 | 缺失项 + 已识别 evidence | `NEED_REVIEW` 结构提示（**非 FAIL**） |
| `test_sheet_waiver_note` | 汇总=是（或状态不清），K.02.2 或汇总 notes 含受限/不执行说明 | 说明原文 + 缺表项 | `NEED_REVIEW`：程序包不完整≠未执行，请确认是否应在汇总同步拒绝 |
| `unclear` | 不足以判断 | 识别失败原因 | `NEED_REVIEW` |

### 已实现（评审对齐）

- `disposal_test_package_complete`：汇总=否 → 不检查三表；缺表 → `NEED_REVIEW`；测试页说明 → `test_sheet_waiver_note` 类消息。
- `ingest/k02_test_sheet.py`：轻量读取 K.02.2 受限执行说明。

### 待做（P1.5）

- `disposal_execution_consistency`：汇总=是 + K.01 处置=0 或 &lt;TE，与测试页说明交叉核对。

## 四、DT-B 处置清单读取

### SOP 口径

- 获取当期按 **资产类别** 划分的处置清单（可含处置损益信息），与 **K.01 后推** 核对；差异 **&gt; SAD** 须调查。
- 格式不固定，但必需字段须完整：**类别、编号、名称、原值、累计折旧、减值、净值、处置日期、减少方式**。
- 清单无法取得时，可自行编制（两年 FA list + JE）；Agent 仍按字段语义识别。
- K～P 列等 SAP 加权参考列 **不是** 处置测试本体，ingest 可忽略或仅 report 备注。

### ingest 需要读取

| 标准字段 | 常见表头变体 | 注意 |
| --- | --- | --- |
| `asset_category` | 固定资产类别、资产类别 | |
| `asset_id` | 卡片编码、编号、固定资产编号 | **禁止**将「单据编号」作 asset_id |
| `asset_name` | 资产名称、固定资产名称 | |
| `original_value` | 原值、处置原值 | 非 FA list「期初原值」语义 |
| `accumulated_depreciation` | 累计折旧、处置累计折旧 | |
| `impairment_provision` | 减值、减值准备 | 可选 |
| `net_value` | 净值、处置净值 | 勾稽核心 |
| `disposal_date` | 处置日期、业务日期、减少日期 | 「业务日期」优先映射处置日期 |
| `disposal_method` | 减少方式、处置/报废、处置方式、处置情况 | 与 `addition_method` 区分 |

### 识别策略

- **名称**：`处置清单`、`减少清单`、`K.02.2b`+清单语义。
- **内容签名**：`处置/报废日` + 原值 + 累折 + 净值 + `出售价格` / `处置损益` / `出售价格差异`。
- **防误判**：P0 `_resolve_name_over_content`，避免内容像 K.01 后推而覆盖 `disposal_list`。
- **表头行**：跳过 SOP 说明整段文字误当表头（案例 G）。

### report 展示

- 来源 sheet、记录数、字段映射、缺失必需字段。
- `disposal_method` 分布（出售 / 报废 / 其他）。
- 出售+报废 **净值合计**（见 DT-C，勿与全清单含「其他减少」混淆）。

### rules 边界（P0 后）

| rule_id | 自动化 | 说明 |
| --- | --- | --- |
| `disposal_required_fields` | AUTO_FAIL | 必需字段缺失 |
| `disposal_date_reasonable` | AUTO_WARN | 处置日期晚于期末 |

## 五、DT-C 样本总体定义

### SOP 口径

- 处置测试样本总体 = **出售 + 报废** 导致的固定资产 **净值** 减少。
- **其他减少**（调拨、重分类、合并、存货/投房转出等）→ 另设总体 / 其他 PSP·OSP（DT-003）。
- **资产处置损益** 不在 K.02.2 总体内 → **U_exp SWP other** 等损益底稿。
- 处置清单中应检查减少方式是否均为出售/报废；若不是，应分层或 NEED_REVIEW。

### ingest 需要读取

**从处置清单（明细层）：**

- 按 `disposal_method` 分类汇总 **净值**。
- 出售类、报废类、其他类行数与金额。

**从 K.02.2（总体层，锚点扫描，不绑死 E14）：**

| 锚点 | 含义 |
| --- | --- |
| `样本总体` / `测试总体` | 文字描述 |
| `处置/报废总金额` / `E14` | 出售+报废净值合计 |
| `Breakdown中处置/报废金额` / `G14` / `I14` / `K14` | 按减少方式拆分小计（出售 / 报废 / 其他） |
| `Breakdown` / `后推` / `K.01` / `差异` / `Notes` | 与后推勾稽区 |

**汇总工具：**

- `disposal_common`（规划）：`is_sale_or_scrap_method()` + `sum_disposal_net_value(records, mapped_fields)`。

### report 展示

- 总体描述原文。
- 出售净值、报废净值、其他减少净值（若有）。
- `处置/报废总金额`（若读到）与清单侧出售+报废合计对照。
- 非出售/报废行数及示例。

### rules 边界

| rule_id | 说明 |
| --- | --- |
| `disposal_population_homogeneity` | REVIEW：存在其他减少方式时提示分层 |
| SP-001 / DT-003 | 特殊性质减少是否单独测试 |

## 六、DT-D 总体金额勾稽

### SOP 口径

- 处置清单净值合计应与 **K.01 BKD 处置/减少** 变动金额（**净值口径**）核对一致。
- K.02.2 上 **处置/报废总金额**（出售+报废净值）亦应与 K.01 处置金额一致。
- 差异 &gt; SAD 须调查说明；与 FA list、清单之间差异若评估不重大可继续测试并说明。

### ingest 需要读取

| 左侧 | 右侧 | 口径 |
| --- | --- | --- |
| 处置清单：出售+报废 **净值合计** | K.01 movement `disposal` × `net_value` | 优先矩阵 triplet 汇总（同购置 P0-2） |
| K.02.2：处置/报废总金额（若可读） | 同上 | 三角核对 |
| 差异 / Notes | K.02.2 或 K.01 调查区 | 摘录，不强判充分性 |

**勿用：**

- 清单 **原值** 合计对 K.01 处置行。
- 单列某类别审定数代替合计。
- 处置 **损益** 科目金额。

### report 展示

- 三方金额：清单（出售+报废净值）、K.02.2 处置/报废总金额（若有）、K.01 处置行。
- 差异、Lead SAD、是否超过 SAD。
- 说明摘录。

### rules 边界

| rule_id | 自动化 | 前置 |
| --- | --- | --- |
| `disposal_rollforward_reconciliation` | AUTO_WARN | DT-B + K.01 处置行稳定 |
| `disposal_difference_over_sad` | AUTO_WARN | 差异 + SAD 可读 |

读不到任一侧 → `NEED_REVIEW`，不强判 PASS/FAIL。

## 八、人工质检补充口径（2026-06-11）

以下口径来自人工质检经验，用于指导后续 report、rules 与 LLM 语义复核设计。

| # | 人工质检点 | Agent 处理口径 |
| --- | --- | --- |
| 1 | 汇总页对不执行理由已有规定及提示词 | 类比现有汇总页判断：结构化读取理由，由 LLM 结合提示词做语义复核；规则层不只按关键词判充分。 |
| 2 | 其他减少通常类比处置处理 | 其他处置/减少净额超过 TT 时，应提示人工确认是否需要单独考虑、分层或另设总体。 |
| 3 | 报废/处置证据不要求全部取得 | Agent 先摘录底稿登记的信息和证据描述；证据充分性由 LLM/人工判断，并提示当前仅核对登记信息，尚未与实际单据核对。 |
| 4 | 固定资产样本量小于 5 可以接受 | K.02.2a 样本量小于 5 不作为异常；仅摘录工具说明、样本量和接受理由。 |
| 5 | 差异解释和原因是否合理 | 需要 LLM 理解 Notes 的具体原因和解释是否合理；规则层仅判断差异金额、是否有说明、是否超过 SAD。 |
| 6 | 处置资产不应仍在期末 FA list | 对 K.02.2 测试样本 / 处置清单资产编号与期末 FA list 做交叉检查；若仍存在，提示人工复核是否未转出或清单口径不一致。 |

### 证据充分性口径

报废常见证据包括但不限于：

- 固定资产报废/处置申请单或审批单。
- 技术鉴定文件、报废鉴定书（大项目更常见）。
- 残值收入及清理费用凭证，如银行回单、收据、发票等。

出售/处置常见证据包括但不限于：

- 处置/出售审批文件（国企、央企等场景更常见）。
- 处置协议或买卖合同。
- 收款凭证，如银行回单、发票等。

这些资料并非全部必须取得。质检时应结合资产性质、金额、处置方式、项目风险和底稿说明判断证据是否充分；Agent 只能先摘录登记内容与证据描述，不能替代对实际单据的人工核对。

### 可规则化与 LLM 分工

| 事项 | 自动规则 | LLM / 人工 |
| --- | --- | --- |
| 汇总页是否选否、是否有理由 | 可读取、可门控 | 理由是否充分需 LLM 复核 |
| 其他减少净额是否超过 TT | 可提示 | 是否单独成总体需人工判断 |
| 样本量小于 5 | 不报异常 | 仅在说明缺失或工具结果异常时复核 |
| 差异是否超过 SAD、是否有 Notes | 可判断 | Notes 是否合理需 LLM 复核 |
| 证据描述是否存在 | 可检查 | 证据是否充分、是否需看实际单据需人工/LLM |
| 处置资产是否仍在期末 FA list | 可交叉检查 | 若命中，原因需人工判断 |

## 十、建议开发顺序

1. **评审本文 DT-A～D**（你当前步骤）。
2. **P0 ingest**：DT-B 处置清单字段 + 分类防误判；DT-C `disposal_common`；DT-D K.01 处置行验证。
3. **P0 report**：处置清单摘录 + 方法分布 + 勾稽三角 + 执行路径。
4. **P0 rules**：`disposal_required_fields`、`disposal_rollforward_reconciliation`（ingest 门禁通过后）。
5. **P1.5 rules**：`disposal_other_reduction_over_tt`、`disposal_asset_removed_from_fa_list`。
